# Đa ngôn ngữ Việt Nam - Nhật Bản

Ứng dụng hiện hỗ trợ `vi` và `ja` ở phía trình duyệt. Ngôn ngữ mặc định là tiếng
Việt và lựa chọn được lưu trong `localStorage` với key `lang`.

## Các file liên quan

| File | Vai trò |
|---|---|
| `src/i18n/vi.ts` | Từ điển tiếng Việt có cấu trúc |
| `src/i18n/ja.ts` | Từ điển tiếng Nhật và bảng `jaUi` cho giao diện cũ |
| `src/lib/i18n.tsx` | `LangProvider`, `useLang` và bộ dịch DOM tương thích |
| `src/components/layout/sidebar.tsx` | Nút chọn `VI` / `日本語` |

`LangProvider` được đặt trong layout của vùng authenticated. Trang login hiện tự
quản lý các nhãn cần thiết nên khi thêm chuỗi ở login phải kiểm tra riêng trang
này.

## Cách lấy ngôn ngữ trong component

```tsx
"use client";

import { useLang } from "@/lib/i18n";

export function Example() {
  const { lang, t, tr } = useLang();

  return (
    <>
      <h1>{t.common.dashboard}</h1>
      <button>{lang === "ja" ? "保存" : "Lưu"}</button>
      <p>{tr("Đang tải...")}</p>
    </>
  );
}
```

Ưu tiên theo thứ tự:

1. Dùng key có cấu trúc trong `vi.ts` và `ja.ts` cho nhãn dùng lại nhiều nơi.
2. Với nội dung chỉ có ở một component, dùng điều kiện `lang === "ja"` để chuỗi
   nằm sát giao diện và dễ kiểm tra.
3. `tr(text)` hoặc `jaUi` chỉ nên dùng cho màn hình cũ chưa chuyển hoàn toàn sang
   key có cấu trúc.

## Thêm một key mới

Hai file phải có cùng section và cùng key:

```ts
// src/i18n/vi.ts
common: {
  expandAll: "Mở rộng tất cả",
}

// src/i18n/ja.ts
common: {
  expandAll: "すべて展開",
}
```

Sau đó dùng `t.common.expandAll`. TypeScript suy ra cấu trúc từ từ điển tiếng
Việt nên thiếu key tương ứng ở tiếng Nhật sẽ được phát hiện khi build.

## Bộ dịch tương thích cho giao diện cũ

`src/lib/i18n.tsx` tạo bảng dịch từ từ điển có cấu trúc và `jaUi`, sau đó dùng
`MutationObserver` để dịch text node cùng các thuộc tính `placeholder`, `title`
và `aria-label`. Cơ chế này giúp các màn hình cũ hoạt động nhưng có các giới hạn:

- Dịch dựa trên chuỗi tiếng Việt chính xác; thay đổi dấu câu có thể làm mất bản
  dịch.
- Chuỗi ghép động có thể chỉ được dịch một phần.
- API error bằng tiếng Anh không tự động có bản dịch.
- MutationObserver có chi phí chạy ở client; màn hình mới nên dùng `t`/`lang`
  trực tiếp.

Không thêm bản dịch trùng hoặc quá ngắn vào `jaUi` nếu nó có thể thay thế nhầm
một phần của chuỗi khác.

## `data-i18n-ignore`

Gắn thuộc tính này khi nội dung đã được component tự chọn đúng ngôn ngữ, hoặc khi
đó là dữ liệu không được dịch như mã task, username, tên người và tên sản phẩm:

```tsx
<span data-i18n-ignore>
  {lang === "ja" ? `${count} タスク` : `${count} task`}
</span>
```

Nếu không gắn, bộ dịch DOM có thể dịch lần thứ hai hoặc thay đổi dữ liệu động.

## Quy ước nội dung

- Mã trạng thái trong database/API giữ nguyên: `PLANNED`, `IN_PROGRESS`,
  `WAITING`, `COMPLETED`, `CANCELLED`.
- Mã độ ưu tiên giữ nguyên: `LOW`, `MEDIUM`, `HIGH`, `URGENT`.
- Chỉ dịch nhãn hiển thị; không dịch ID, code hoặc giá trị gửi lên API.
- Tên người, nhóm và sản phẩm do người dùng nhập được giữ nguyên.
- Thuộc tính `<html lang>` được `LangProvider` đổi giữa `vi` và `ja`.

## Checklist khi sửa giao diện

1. Chuyển qua lại `VI` và `日本語` trên đúng màn hình.
2. Kiểm tra text, placeholder, tooltip, hộp thoại alert/confirm và trạng thái rỗng.
3. Kiểm tra chuỗi có số hoặc dữ liệu ghép động.
4. Chuyển lại tiếng Việt để đảm bảo không còn text Nhật bị giữ lại.
5. Kiểm tra cả light mode và dark mode.
6. Chạy `npm run lint` và `npm run build`.
